Example

Below is an example of a basic Date Picker.

Days

The input is a section-based mask — type the date directly, adjust a section with the arrow keys, or pick a day from the calendar. There is no free-text parsing and no debounce: the field always holds a valid partial date.

html
<div class="row">
  <div class="col-sm-6 col-lg-5 mb-4 mb-sm-0">
    <div data-coreui-locale="en-US" data-coreui-date-picker></div>
  </div>
  <div class="col-sm-6 col-lg-5">
    <div data-coreui-date="2026/03/15" data-coreui-locale="en-US" data-coreui-date-picker></div>
  </div>
</div>

With footer

There is no footer option. Project a <template data-coreui-template="footer"> child instead — its content is cloned into the dropdown. Buttons act through data-coreui-picker-action (today, clear, reset, close), so labels, order, and translations are yours. A button opting into the today action opts into its state too: it is disabled at initialization when today falls outside minDate/maxDate/disabledDates. This is one-way — the picker only ever sets disabled, so a button you disable in the template stays disabled.

html
<div class="row">
  <div class="col-lg-5">
    <div data-coreui-locale="en-US" data-coreui-date-picker>
      <template data-coreui-template="footer">
        <button type="button" class="btn-ghost theme-danger btn-sm me-auto" data-coreui-picker-action="today">Today</button>
        <button type="button" class="btn-ghost theme-primary btn-sm" data-coreui-picker-action="clear">Clear</button>
        <button type="button" class="btn-solid theme-primary btn-sm" data-coreui-picker-action="close">OK</button>
      </template>
    </div>
  </div>
</div>

Here maxDate is the end of last month, so the today button disables itself. The state of any other button is yours — the slot context exposes isDateSelectable(date), which answers whether a date, expressed in the field’s mask, passes the minDate/maxDate/disabledDates validation (a day mask checks the calendar day, so new Date() passes with a maxDate of today, and a month, quarter or year mask checks the whole period) — and every programmatic date still runs through the field’s validation: out of range, the field turns is-invalid, errorChange reports the reason, and getDate() reports null, the same outcome as typing that date. setDate() fires no dateChange; an action such as today fires it with null.

html
<div class="row">
  <div class="col-lg-5">
    <div id="myDatePickerFooterToday">
      <template data-coreui-template="footer">
        <button type="button" class="btn-ghost theme-danger btn-sm me-auto" data-coreui-picker-action="today">Today</button>
        <button type="button" class="btn-solid theme-primary btn-sm" data-coreui-picker-action="close">OK</button>
      </template>
    </div>
  </div>
</div>
js
const myDatePickerFooterToday = document.getElementById('myDatePickerFooterToday')

const datePickerFooterToday = new coreui.DatePicker(myDatePickerFooterToday, {
  locale: 'en-US',
  maxDate: new Date(new Date().getFullYear(), new Date().getMonth(), 0)
})

Weeks

Add data-coreui-selection-type="week" to select week numbers, and data-coreui-show-week-number="true" to show them in the grid. The field renders the native <input type="week"> presentation — a fixed, non-editable localized label followed by the week and year sections (Week 29, 2026, Tydzień 29, 2026, …). The year is the ISO week-numbering year, which can differ from the calendar year around January 1st, and the reported Date is the Monday of the selected week. Prefer the ISO wire format in the field? Set data-coreui-format="yyyy-Www".

html
<div class="row">
  <div class="col-lg-5">
    <div
      data-coreui-locale="en-US"
      data-coreui-selection-type="week"
      data-coreui-show-week-number="true"
      data-coreui-date-picker></div>
  </div>
</div>

With time

Set timepicker to add the time half. The field switches to a date and time mask, the panel grows a row of time selects under the calendar, and picking a day no longer closes the panel — the two halves own different parts of one value, so the interaction is not over until the user says so. While no time is picked, or the field holds a time a list does not offer, each select stands on a -- placeholder, so every enabled option, the first allowed one included, sets the time.

html
<div class="row">
  <div class="col-lg-5">
    <div data-coreui-locale="en-US" data-coreui-timepicker="true" data-coreui-date-picker></div>
  </div>
</div>

hours, minutes and seconds narrow what the time half offers, and are ignored without timepicker. Hours are 0 to 23 in every locale; on a 12-hour clock an hour that only one period allows sets that period. The four ariaSelect*Label options name its selects, and with the flag on the field actions call themselves “Clear date and time” and “Toggle calendar and time selection” unless the page passed its own label.

minDate and maxDate can carry a time of day. Their day stays selectable in the calendar and the time selects disable the hours, minutes and seconds before minDate or after maxDate on that day. A time the panel sets beyond a limit, such as the current time when the day of minDate is picked, moves to the limit; a typed time beyond it marks the field invalid. Until a date is picked, the time selects work on today moved into the limits. A limit without a time of day covers its whole day.

html
<div class="row">
  <div class="col-lg-5">
    <div data-coreui-locale="en-US" data-coreui-timepicker="true" data-coreui-min-date="2026-10-15T09:30" data-coreui-max-date="2026-10-30T17:00" data-coreui-date-picker></div>
  </div>
</div>

Wrap the control in .form-field to lay it out with its label and description, and to get validation feedback in the right place.

Delivery date

<div class="form-field">

</div>

Composing the markup

The picker is built from other components — the date input field, the calendar and a popup — held together by the date it owns. The markup is where you choose the parts: mark an element with a role attribute and the picker adopts it instead of building its own; leave a part out and it is generated as in the examples above.

RoleElementWhat the picker does with it
data-coreui-picker-fielda divHosts the date input’s sections. Without it the field is generated (and wrapped in .form-floating when floatingLabel is set).
data-coreui-picker-togglea button or any elementOpens and closes the calendar. Gets aria-expanded and aria-haspopup, and aria-controls while the calendar is open, and ariaPickerLabel as its name unless it has one or shows text of its own.
data-coreui-picker-cleanera buttonClears the value. Gets ariaCleanerLabel as its name unless it has one or shows text of its own.

A decorative <svg> inside an adopted button is marked aria-hidden for you. So a trigger can be a regular button with its own text and icon, the way a combobox has one:

html
<div data-coreui-locale="en-US" data-coreui-date-picker>
  <div data-coreui-picker-field></div>
  <button type="button" class="btn btn-subtle btn-sm" data-coreui-picker-cleaner>
    <svg viewBox="0 0 16 16" width="16" height="16" fill="none" stroke="currentColor" stroke-width="1.5"><path d="M3 3l10 10M13 3L3 13"/></svg>
  </button>
  <button type="button" class="btn btn-subtle btn-sm" data-coreui-picker-toggle>
    <svg viewBox="0 0 16 16" width="16" height="16" fill="none" stroke="currentColor" stroke-width="1.5"><rect x="1.5" y="2.5" width="13" height="12" rx="1.5"/><path d="M1.5 6.5h13M5 1v3M11 1v3"/></svg>
    Pick a date
  </button>
</div>

The cleanerIcon and pickerIcon options only feed the generated buttons; with your own markup the icon is whatever you put in the HTML, and nothing is sanitized because nothing is rendered from a string.

Floating labels

The date picker supports floating labels: set floatingLabel and the component renders the label itself — no wrapper markup needed — and the text also becomes the field’s accessible name. The mask placeholders stay hidden while the label rests inside the field; focusing any part of the field — the sections or the picker button — floats the label and reveals the mask.

html
<div data-coreui-locale="en-US" data-coreui-floating-label="Delivery date" data-coreui-date-picker></div>

Add .form-floating-always to the component element to keep the label always floating with the mask showing.

Disabled dates

The disabledDates option excludes specific dates — single Dates, [start, end] ranges, or a matcher function. The calendar grays them out and the field refuses them: a completed date that hits a disabled entry gets the .is-invalid class and the picker reports null, and submits no date, until it is corrected. In week, month, quarter and year selection the calendar and the field judge the whole period: it is refused only when it lies wholly before minDate or after maxDate, or disabledDates covers every day of it that the limits leave. In week selection the limits count as whole weeks, so for a week that is all seven days.

html
<div class="row">
  <div class="col-lg-5">
    <div id="myDatePickerDisabledDates"></div>
  </div>
</div>
js
const myDatePickerDisabledDates = document.getElementById('myDatePickerDisabledDates')

const datePickerDisabledDates = new coreui.DatePicker(myDatePickerDisabledDates, {
  locale: 'en-US',
  date: new Date(2026, 6, 10),
  disabledDates: [
    [new Date(2026, 6, 4), new Date(2026, 6, 7)],
    new Date(2026, 6, 16)
  ],
  minDate: new Date(2026, 6, 1),
  maxDate: new Date(2026, 6, 31)
})

myDatePickerDisabledDates.addEventListener('dateChange.coreui.date-picker', event => {
  console.log('dateChange', event.date)
})

Disabling weekends

Pass a function to disable every date that matches a rule.

html
<div class="row">
  <div class="col-lg-5">
    <div id="myDatePickerWeekends"></div>
  </div>
</div>
js
const myDatePickerWeekends = document.getElementById('myDatePickerWeekends')

const datePickerWeekends = new coreui.DatePicker(myDatePickerWeekends, {
  locale: 'en-US',
  disabledDates: date => date.getDay() === 0 || date.getDay() === 6
})

Validation

The picker shows its validation state on the frame and on the sections of its field, which the message after the picker describes, the way the form plugin does for a native field. The field keeps its value in a <textarea> laid invisibly over it, so a required picker that is empty, incomplete or holds a rejected date blocks the submit, as the date input does.

You give a state with the validationState option ('valid', 'invalid' or a state of $form-validation-states, with invalid and valid as deprecated aliases) or with an .is-invalid or .is-valid class written on the picker element, the server-side route, which is read once, when the picker starts; the option wins over the class. A given state is a verdict on the date it was given for, so the next change of the date the user makes drops it: a day picked in the calendar, a time picked with timepicker, the cleaner, a footer button that changes the date through the context, or typing in the field. An action that leaves the date as it is keeps the state. A change your own code makes, with setDate(), clear(), reset() or today(), keeps it. setValidationState() sets it again without rebuilding the picker. A class or an aria-invalid written on the picker element after it starts is not read. While the given state is 'invalid', the picker blocks the submit with the text of the message after it, or Invalid value. when there is none. A native form reset puts back the date the picker started with and drops the state.

We have no delivery slots left on this date.
html
<div class="row">
  <div class="col-lg-5 form-field">
    <div class="is-invalid" data-coreui-date-picker data-coreui-locale="en-US" data-coreui-date="2026-07-14"></div>
    <div class="invalid-feedback">We have no delivery slots left on this date.</div>
  </div>
</div>

Custom formats

The mask of the field defines the format. Set it with data-coreui-format (or the format option), which the field forwards from the shell. The parser accepts both dayjs/moment-style tokens (DD, MM, YYYY, YY) and date-fns/Unicode-style tokens (dd, MM, yyyy, yy), plus ww for ISO week numbers and q (numeric) or QQQ (Q1–Q4) for quarters; any other character becomes a literal separator.

html
<div class="row">
  <div class="col-sm-6 col-lg-5 mb-4 mb-sm-0">
    <label class="form-label" id="datePickerDdMMYyyyLabel">dd.MM.yyyy</label>
    <div data-coreui-format="dd.MM.yyyy" data-coreui-locale="en-US" data-coreui-date-picker aria-labelledby="datePickerDdMMYyyyLabel"></div>
  </div>
  <div class="col-sm-6 col-lg-5">
    <label class="form-label" id="datePickerYYYYMMDDLabel">YYYY-MM-DD</label>
    <div data-coreui-format="YYYY-MM-DD" data-coreui-locale="en-US" data-coreui-date-picker aria-labelledby="datePickerYYYYMMDDLabel"></div>
  </div>
</div>

A format does not have to include every section — a month-and-year mask reports the first day of the month.

html
<div class="row">
  <div class="col-lg-5">
    <div data-coreui-format="MMMM yyyy" data-coreui-locale="en-US" data-coreui-date-picker></div>
  </div>
</div>

Accessibility

The field is a date input — a group of spinbutton sections — so its own arrow keys belong to the value, and the popup opens on the native control’s dropdown keys. Focus enters the calendar on the selected date, else on today or on the minDate / maxDate today falls outside of, also when that date cannot be picked: it is announced as unavailable and the arrows move on from it. In week selection it enters on the row of that week.

Clicking a label that names the field, through aria-labelledby or a <label for> pointing at the element, moves focus to the first empty section of the field.

An aria-label, aria-labelledby or aria-describedby on the picker element moves to the field, so a screen reader announces the name and the description when focus enters it, and the picker element gets them back on dispose. Point aria-labelledby at the visible label, as the examples on this page do; it names the field over floatingLabel and an ariaLabel in inputOptions, the way the browser ranks names. A data-coreui-picker-field you wrote that already has an aria-label or aria-labelledby keeps its own name, and its own aria-describedby comes first, followed by the one that moves.

While the picker shows an invalid state, the sections of its field carry aria-invalid="true" and are described by the error message after the picker, see Validation. An aria-invalid written on the picker element is not read; give the state with validationState or with the class.

The toggle’s name ends with the date the picker holds, written in full (Toggle calendar, Friday, August 14, 2026, with the time after it with timepicker), so a screen reader reads the picked date when the popup closes and focus goes back to the toggle. A live message would be lost at that moment, so the calendar does not announce a pick that closes the popup onto that toggle. With timepicker the popup stays open, and the calendar announces the pick through ariaSelectedDateAnnouncement; it does the same without a toggle (pickerIcon: false) and with a data-coreui-picker-toggle that has a name or text of its own, which keeps it unchanged.

Keyboard support

KeyAction
Alt (Option on macOS) + Arrow Down / F4Open the calendar popup and move focus into the grid
EscapeClose the popup and return focus to the field or the toggle that opened it
Tab / Shift + TabMove within the open calendar; the field is outside the dialog and stays out of the cycle
Arrow Right / Arrow LeftMove focus to the next / previous day; crossing the edge of the grid moves to the adjacent month
Arrow Down / Arrow UpMove focus to the same day of the next / previous week
Home / EndMove focus to the first / last day of the week inside minDate / maxDate, into the previous / next month when the week starts or ends there
Page Down / Page UpMove focus to the same day of the next / previous month, keeping the day number when the target month is long enough; a series of presses keeps the day it started from, so January 31 goes to February 28 and then March 31, also across a stop at minDate / maxDate; any other key or a click starts a new series
Shift + Page Down / Shift + Page UpMove focus to the same day of the next / previous year, keeping the day of a series the same way
Enter / SpaceSelect the focused date, and close the popup unless timepicker is on, where the time half still has to be set; nothing happens on a date that cannot be picked

In the calendar grid, a key from the table pressed with Alt, Ctrl or Cmd is neither handled nor cancelled: focus stays where it is and the key stays free for the browser and assistive technology.

Usage

Via data attributes

Add data-coreui-date-picker to a div element.

<div data-coreui-date-picker></div>

Inside it, data-coreui-picker-field, data-coreui-picker-toggle and data-coreui-picker-cleaner name the parts you supply yourself — see Composing the markup.

Via JavaScript 

<div class="my-date-picker"></div>
const datePickerElementList = Array.prototype.slice.call(document.querySelectorAll('.my-date-picker'))
const datePickerList = datePickerElementList.map(datePickerEl => {
  return new coreui.DatePicker(datePickerEl)
})

Options

Options can be passed via data attributes or JavaScript. For data attributes, append the option name to data-coreui-, converting “camelCase” to “kebab-case” — write data-coreui-selection-type="week", not data-coreui-selectionType="week".

Options belonging to the inner calendar, date input or, with timepicker, the time columns of the time picker are forwarded by name, so their data attributes work on the picker element too. The calendar’s startDate and the time columns’ hourCycle, onChange and time are set by the picker itself.

PropertyTypeDefault
allowListobjectSVGAllowlist

Allowlist used when sanitizing the icon markup.

ariaCleanerLabelstring'Clear date'

Accessible label of the cleaner button. 'Clear date and time' with timepicker while the default is kept.

ariaLabelstring'Date input'

Accessible name of the field. It lands on the role="group" container the sections sit in, so it names the whole control rather than one part of it.

ariaPickerLabelstring'Toggle calendar'

Accessible label of the picker button, followed by the date the picker holds. 'Toggle calendar and time selection' with timepicker while the default is kept.

Slot context

Projected regions (and any custom code) drive the picker through a small imperative contract instead of configuration:

const picker = coreui.DatePicker.getOrCreateInstance(element)
const context = picker.getContext()

context.today()          // set today's date
context.setDate(date)    // set any date
context.clear()          // clear the value
context.reset()          // restore the initial value
context.close()          // close the popup
context.date             // current value (Date | null)
context.disabled         // disabled state

Events

EventDescription
dateChange.coreui.date-pickerFired when the value changes — from the calendar, the field, or a context action. event.date is the validated Date, or null; event.formattedDate is the same value in the shape of selectionType (2026-01, 2026W03, 2026Q1, 2026, or the Date itself for day), with the year in at least four digits (0026-01).
hidden.coreui.date-pickerFired once the popup has finished its exit transition and left the page. Skipped when the popup reopens first.
hide.coreui.date-pickerFired immediately when hide is called — by the API, the indicator, Escape or an outside click. Call event.preventDefault() to keep the popup open.
show.coreui.date-pickerFired immediately when show is called. Call event.preventDefault() to keep the popup closed.
shown.coreui.date-pickerFired once the popup has finished its entry transition. Skipped when the popup closes first.

The field’s own events (dateChange.coreui.date-input, errorChange.coreui.date-input) still bubble from the inner element — the shell does not duplicate them. dateChange.coreui.date-picker fires before the field’s errorChange for the same change, whether it comes from the calendar, the field or an action, so a date an errorChange listener sets replaces the one just reported.

const myDatePicker = document.getElementById('myDatePicker')
myDatePicker.addEventListener('dateChange.coreui.date-picker', event => {
  console.log(event.date)
})

Customizing

CSS variables

The field is a .form-control-group on the picker element itself, so its frame, the cleaner and the toggle read the --cui-control-* and --cui-control-group-* tokens. Set them on the picker element to restyle one field.

The picker declares its local CSS variables on its panel, .date-picker-popup, for real-time customization. Values are set via Sass, so Sass customization is supported too.
