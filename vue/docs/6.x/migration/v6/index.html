CoreUI for Vue is the Vue.js version of the CoreUI components library, so before reading this migration guide, please also check the CoreUI 5 to 6 migration guide — it covers the markup, class names, Sass architecture and design tokens this release is built on. This page covers what changes in the Vue API.

Dependencies

  • Breaking Popper is gone; positioning runs on Floating UI. @popperjs/core is replaced by @floating-ui/dom. Update your lockfile — nothing else is required for the default configuration.
  • Breaking popperConfig is now floatingConfig on CDropdown, CPopover and CTooltip, and it takes a Floating UI ComputePositionConfig instead of a Popper one. The popper boolean prop stays and still switches static positioning.
  • Breaking Positioned elements are stamped with data-coreui-placement, not data-popper-placement. Custom CSS, tests or scripts keyed on the old attribute must be updated. The v6 stylesheet draws tooltip, popover and menu arrows from this attribute, so it is not optional.
  • Breaking The exported composables are renamed: usePopper → useFloating, useDropdownWithPopper → useDropdownWithFloating.

New components

  • CCombobox — a .form-control toggle over a popup list box: the options are CListBoxOption children or an items array, the selection is single or multiple, the panel takes an optional search field with searchNormalize, and name submits the value through a hidden select that takes part in form validation. Ships with the useCombobox() composable.

  • CDateInput, CTimeInput — section fields: a masked, keyboard-first input where every part of the value (day, month, year, hour…) is its own editable section. <CDateInput type="datetime"> carries the time too. The pickers are built on them, and they work standalone.

  • CDialog and CDrawer — the native-<dialog> popup and side panel with the Bootstrap 6 look and the dialog-* / drawer-* classes. CDialog is a centered floating panel over a blurred backdrop with optional slide-in variants; CDrawer is a floating, inset, rounded panel with sheet, translucent, fit-content and fullscreen variants plus responsive breakpoints. CDialog’s fullscreen takes a breakpoint as well as true, like CModal’s.

    They share their behavior with CModal and COffcanvas, which keep the classic look and the v5 vocabulary — and one event vocabulary of their own: show, close and close-prevented on both, where the legacy pair says hide. CModal and COffcanvas are deprecated and may be removed in v7 — prefer CDialog and CDrawer for new work. Pick one per surface; they are independent components.

  • CListBox — the ARIA listbox pattern as a component: single, multiple or no selection, sections, descriptions, link options, an empty state, typeahead and an activeDescendant mode that keeps the focus in your own input. Ships with CListBoxOption, CListBoxSection, CListBoxEmpty, the header parts (CListBoxHeader, CListBoxSelectAll, CListBoxTitle, CListBoxSubtitle) and the useListBox() composable.

  • CMenu — contextual overlays with submenus, container teleport, responsive placement and logical (start/end) placements. Ships with CMenuToggle, CMenuContent, CMenuItem, CMenuHeader, CMenuDivider, CMenuText, CSubmenu and the useMenu() composable. See the Menu docs.

  • CNumberInput — a number field with a stepper you can hit, in place of the browser’s own spinner (tiny in some engines, absent on iOS). min, max and step stay native.

  • CTransfer — two list boxes and four buttons that move values between them, with a select-all header and counter per list, an optional search, a one-way mode and an announcement of every move through announce(). Ships with the useTransfer() composable.

Field components

CAutocomplete, CMultiSelect, CDatePicker, CDateRangePicker and CTimePicker are built on one frame and one panel. These two changes apply to all five; the per-component sections below cover what is specific to each.

  • Breaking A field component is the frame. It carries .form-control-group on its own root instead of nesting one, so a field is a direct child of an .input-group like any other control and there is no wrapper level to reach through. Custom CSS written as .date-picker .form-control-group no longer matches anything. On the pickers, the label and the validation feedback also move out of the frame.

    The frame replaces the per-component shells: .autocomplete-input-group, .form-multi-select-input-group and their -sm/-lg variants are gone, the adornments are .form-control-cleaner / .form-control-action (replacing .autocomplete-cleaner, .form-multi-select-cleaner, .autocomplete-indicator, .form-multi-select-indicator), and the size prop puts .form-control-sm / .form-control-lg on the frame itself.

  • Breaking The options/picker panel exists only while it is open. It is built when the field opens and removed once the exit transition has played, so a closed field carries no panel markup at all — code that queried .combobox-popup or .date-picker-popup up front, or held a ref to it across a close, needs to look it up per open.

Theme colors

Breaking light and dark are replaced by inverse. They were theme colors named after a color scheme and neither followed one: <CButton color="dark"> stayed near-black on a near-black page. There are seven colors now — primary, secondary, success, info, warning, danger, inverse — and the runtime validator lists them, so color="dark" and color="light" warn in the console instead of passing silently.

  • color="dark" becomes theme="inverse". inverse resolves to gray-900 in light mode and gray-100 in dark, so it stands against the page in both.

  • color="light" becomes theme="secondary". secondary is the light neutral now (gray-100 / gray-600) rather than the mid gray-blue #6b7785, so components already using it change appearance.

  • Where the class was painting a plain panel rather than naming a color, reach for bg-4 or bg-3; where it was a fixed dark backdrop, set data-coreui-theme="dark" on the container.

  • Breaking color on buttons is deprecated in favour of theme. A v6 button is a shape plus a colour: variant picks the shape (solid, outline, subtle, ghost) and theme picks the colour. color renders the v5 spelling btn-{color}, which fuses the two and cannot inherit a colour from an ancestor; it still works and is removed in v7. <CButton color="primary" /> becomes <CButton theme="primary" />, and <CButton color="primary" variant="outline" /> becomes <CButton theme="primary" variant="outline" />. color="link" becomes the link property — a link button is a shape, not a colour, and it takes its colour from the link colour rather than from a theme. color="transparent" is gone with the .btn-transparent class it rendered — use variant="ghost", which shows nothing but the button’s content until hover and carries the base styling on its own.

  • Breaking The theme colour tokens finish their rename. --cui-{color}-text-emphasis is --cui-{color}-fg-emphasis and --cui-{color}-border-subtle is --cui-{color}-border, matching the slot names the components already read. Custom CSS naming the old tokens has to follow; the class names (.text-primary-emphasis, .border-primary-subtle) are unchanged.

  • Breaking The bare theme colour tokens are gone. --cui-primary, --cui-secondary, --cui-success, --cui-info, --cui-warning, --cui-danger and --cui-inverse no longer exist. A theme colour is its set of slots — -base, -bg, -fg, -fg-emphasis, -bg-subtle, -bg-muted, -border, -focus-ring, -contrast — and the colour itself is the -base slot: --cui-primary-base is what --cui-primary was, the 100–900 scale is mixed from it, and -bg (the action background) points at it. Rename reads one to one, in custom CSS and in the inline styles the examples use to retint a component:

    - <CTooltip :style="{ '--cui-tooltip-bg': 'var(--cui-primary)' }" />
+ <CTooltip :style="{ '--cui-tooltip-bg': 'var(--cui-primary-base)' }" />

- :root { --cui-primary: #6f42c1; }
+ :root { --cui-primary-500: #6f42c1; }

    No component prop is affected — theme="primary" is unchanged.

  • Breaking The palette is the theme colours. $colors holds primary, success, info, warning, danger and gray; the ten hues ($blue … $cyan) and every --cui-{hue} and --cui-{hue}-{stop} token are gone, as are $secondary and $inverse. Each $theme-colors entry points base and bg at its palette’s 500 stop and the other slots at that scale; secondary reads --cui-gray-200 and inverse --cui-gray-900. No palette token is bare: the literal sits in -500, so --cui-gray-500 is what --cui-gray was, and --cui-primary-500 is the runtime knob for the whole family:

    - :root { --cui-primary-base: #6f42c1; }
+ :root { --cui-primary-500: #6f42c1; }

- <CBadge :style="{ '--cui-badge-bg': 'var(--cui-teal-600)' }" />
+ <CBadge :style="{ '--cui-badge-bg': 'var(--cui-success-600)' }" />

  • Breaking Under a theme the theme wins over a component color token. A component reads the --cui-theme-* slot on the property and its own token only as the fallback. In v5 the color came from the component’s tokens, so a token you set on a colored alert applied; in v6 a token set on a themed component, or for the whole page in your CSS or a $…-tokens map, changes only the components without a theme. To recolor one themed component, set the slot instead: <CAlert theme="danger" :style="{ '--cui-theme-bg-subtle': '#fde2e4' }">.

  • Variants keep the component token as the override point. Button variants, variant="solid" on an alert, subtle and outline on a badge, subtle on an avatar and outline on a chip map the component tokens to their own slots and paint from the tokens, so there a component token you set wins over the theme. Validation states win over a theme too.

Surface ladder

Breaking The neutral surfaces are a numbered ladder. .bg-body-secondary, .bg-body-tertiary, .text-body-secondary and .text-body-tertiary are deprecated in favor of ordinal names: .bg-1 … .bg-4 for surfaces and .fg-body, .fg-1 … .fg-4 for the text hierarchy, with two new rungs (.bg-1, .bg-2) between the body and the old surfaces. The deprecated names render identically and are removed in v7. The tokens moved with them — --cui-bg-body, --cui-bg-1 … and --cui-fg-body, --cui-fg-1 … are canonical, and --cui-secondary-bg, --cui-tertiary-bg, --cui-secondary-color, --cui-tertiary-color, --cui-body-bg and --cui-body-color remain as aliases until v7. No component prop is affected.

The deprecated surface names sit two rungs lower than they first did: .bg-body-secondary renders --cui-bg-3 and .bg-body-tertiary --cui-bg-2, the v5 stops one rung apart, while .text-body-secondary stays --cui-fg-2 and .text-body-tertiary --cui-fg-3 — tertiary text was the lighter of the two in v5 and still is.

  • Breaking The ladder is three Sass maps, not a row of scalars. $theme-bgs, $theme-fgs and $theme-borders replace $bg-body, $bg-1 … $bg-4, $fg-body, $fg-1 … $fg-4, $border-subtle, $border-muted and $border-emphasized. Each map lives in scss/_theme.scss in the defaults() shape, :root emits every entry as --cui-bg-{key}, --cui-fg-{key} or --cui-border-{key}, and the .bg-*, .fg-* and .border-* utilities are generated from the same maps. $border-color stays a scalar — it is the default every component reads, not a rung. Override an entry instead of a variable:

    - $bg-body: #000;
- $fg-body: #111;
+ $theme-bgs: ("body": #000);
+ $theme-fgs: ("body": #111);

Sass options

  • Breaking $enable-important-utilities is gone with the !important suffix. Utilities are emitted in the last cascade layer, so they already beat every component and modifier without it, and no switch brings the suffix back. The one case it covered is your own unlayered CSS, which beats every layer: move that CSS into @layer custom and utilities win again.
  • Breaking $enable-negative-margins is gone with the .m*-n* utilities. Two negative inline steps ship unconditionally — .me--1, .me--2, .ms--1 and .ms--2 — from the $negative-spacers map; add a key there to extend the set. The block margins have no negative form.

Breakpoints

  • Breaking The xxl breakpoint prop is 2xl, and the three largest breakpoints move. lg is 1024px (was 992), xl 1280px (was 1200) and the top tier is 2xl at 1536px (was xxl at 1400); sm and md are unchanged. A prop whose name starts with a digit needs the shorthand or the colon form in a template — <CCol :2xl="6">, <CContainer 2xl> — and a quoted key in an options object.

    v5v6
    <CCol xxl="6"><CCol :2xl="6">
    <CRow :xxl="{ cols: 3 }"><CRow :2xl="{ cols: 3 }">
    <CContainer xxl><CContainer 2xl>
    <CPlaceholder :xxl="4"><CPlaceholder :2xl="4">
    v-c-placeholder="{ xxl: 4 }"v-c-placeholder="{ '2xl': 4 }"
    <CDropdown :alignment="{ xxl: 'end' }"><CDropdown :alignment="{ '2xl': 'end' }">
    <CDialog fullscreen="xxl">, <CModal fullscreen="xxl">fullscreen="2xl"
    <CDrawer responsive="xxl">, <COffcanvas responsive="xxl">responsive="2xl"
    <CHeader container="xxl">, <CNavbar container="xxl">container="2xl"
    <CNavbar expand="xxl">expand="2xl"
    <CListGroup layout="horizontal-xxl">layout="horizontal-2xl"
    <CTable responsive="xxl">responsive="2xl"

  • Responsive placement reads the new scale. placement="top 2xl:bottom" on CMenu, CPopover and CTooltip replaces the xxl: prefix, and lg:/xl: switch at 1024px and 1280px.

  • The exported Breakpoints type ends in '2xl' instead of 'xxl'.

  • Size variants that spell xxl are not breakpoints and keep their name — CIcon’s size="xxl" among them.

Grid and sizing

  • Breaking A denser spacing scale. $spacers has thirteen steps, 0–12: .25 / .375 / .5 / .75 / 1 / 1.25 / 1.5 / 1.75 / 2 / 2.25 / 2.5 / 3 rem from 1 (v5: .25 / .5 / 1 / 1.5 / 3). Every spacing, gap, space and gutter utility changes value under the same number, and so do the numeric gutter, gutterX and gutterY values of CRow; the v5 steps map to v6 as 1→1, 2→3, 3→5, 4→7, 5→12. p-3 becomes p-5, mb-4 becomes mb-7, <CRow :xs="{ gutter: 3 }"> becomes a gutter of 5. Components keep their size, cards aside (see CCard): their tokens read the stops that carry the v5 values.

  • New: .w-1 … .w-12, one $spacer per step from the $sizes map, alongside the percentage widths — see the width utilities.

  • Breaking $grid-gutter-width is $grid-gutter-x, and $grid-gutter-y joins it. make-row() takes both (make-row($gutter-x, $gutter-y)) and writes them to --cui-gutter-x / --cui-gutter-y; the row gutter defaults to 0 as before, so nothing moves unless you set it. $grid-gutter-width stays as a deprecated alias of $grid-gutter-x until v7 — set the new name, the alias only reads. CRow’s xs/sm… gutter values follow the new spacing scale (see A denser spacing scale).

Z-index

  • New keys in $zindex-levels: menu, drawer, dialog, on the same values as dropdown, offcanvas and modal (1000, 1045, 1055). Each emits a --cui-z-* token and a .z-* utility, and CMenu, CDrawer and CDialog read their own key instead of the legacy component’s. The legacy keys stay; both spellings of a pair always resolve to one number.

Typography

  • Breaking $font-sizes sets a line height per stop instead of one value for all headings. xs is 1.25, sm … lg the body leading (--cui-body-line-height, 1.5), xl 2.5⁄1.75, 2xl 3⁄2.25, 3xl 1.2, 4xl and 5xl 1.1, 6xl 1 — the larger the type, the tighter the leading, and the small stops read at body leading instead of 1.2. The sizes are unchanged. Headings follow their stop through --cui-line-height-*: h5 (lg) and h4 (xl) get taller lines, h1 (4xl) a tighter one. $headings-line-height still feeds --cui-heading-line-height for anything that reads it directly.

Shadows

  • Breaking Every shadow is a stack of two to four layers with a negative spread instead of one wide blur: a tight layer for contact, wider ones for ambient light, each at 4–9 % alpha, so a card reads as lifted rather than smeared. .shadow-xs and --cui-box-shadow-xs are new (one thin layer). The inset shadow reads 8 % in the light scheme and 26 % in the dark one, and --cui-shadow-strength in the dark scheme is 2.4 (was 2.5). The knobs are unchanged: --cui-shadow-color and --cui-shadow-strength on :root, .shadow-{color} and .shadow-opacity-* on the element, $shadows in Sass — a custom entry is now a comma-separated list of layers.

Components

The visible family

  • visible is deprecated in favour of show / v-model:show on CAlert, CDialog, CDrawer, CDropdown, CMenu, CModal, COffcanvas, CPopover, CSidebar, CToast and CTooltip. The old prop was semi-controlled: it fed the internal state, but the component still closed itself, so the prop and reality desynchronized on the first Escape or backdrop click — a confirm-before-close dialog or a pinned tooltip could not be built on it. One prop now covers both needs:

    • show passed one-way seeds the starting state, and the component keeps managing itself from there.
    • v-model:show hands the state to your component. Close and trigger gestures (Escape, a backdrop or outside click, the dismiss button, hover, the autohide timer) then only emit update:show, and nothing moves until you flip the value.
    • update:show — emitted with the requested state either way.

    visible keeps its old behaviour unchanged, is ignored when show is set, and is removed in v7.

  • show replaces visible on the purely controlled components too — CCollapse, CTabPane, CTabPanel and CBackdrop take show, and visible stays as a deprecated alias that loses to it. These never owned their state, so nothing changes in behaviour; the library speaks one word for the same thing.

  • CSubmenu takes show / v-model:show in place of its visible, which was a seed the submenu silently overwrote on hover; a submenu can be controlled now.

  • CNavGroup moves to show / v-model:show. With a v-model:show (or a bare @update:show listener) the group renders what the prop says and the toggler only emits the request; without a listener a bare show is the default-open seed and nothing freezes. visible, v-model:visible and update:visible stay as deprecated aliases — update:visible keeps firing alongside update:show — and the togglerContent slot receives { show } (with visible still present).

Controlled value props

Breaking The value and state props are fully controlled when set — the same contract the visible family moved to, applied to the props that hold a component’s value. They used to be semi-controlled: the prop fed the internal state, but the component still wrote to it, so the prop and reality desynchronized on the first user interaction. Now the component renders exactly what you pass, an interaction only emits, and nothing moves until you feed the change back — a bare value prop without its listener freezes the control. Code that passed one as an initial value migrates to the new default* twin, which seeds the state once, on mount:

componentcontrolled propinitial-value twin
CAutocomplete, CMultiSelectvaluedefaultValue
CButton (toggle mode)activedefaultActive
CChipselecteddefaultSelected

Props that carry a real v-model binding need no twin, and none was added: modelValue on CRangeSlider, CRating, CStepper and COneTimePassword, showPassword on CPasswordInput, openItemKeys on CAccordion, show on the visible family, and date / time / startDate / endDate on the pickers and the date-time inputs all seed the starting state when passed one-way, and hand the state over only once you bind them with v-model.

  • A bare YYYY-MM-DD string is read in the local timezone. Date.parse treats it as UTC midnight, so <CCalendar start-date="2026-07-14" /> landed on the 13th west of Greenwich and at the local offset east of it. Every Vue component that takes a date string is affected — CCalendar, CDatePicker, CDateRangePicker, CDateInput. The vanilla and React editions already read it this way, so this closes a divergence rather than opening one.

  • Breaking The pickers and the date-time inputs drop their default* twins — defaultDate on CDatePicker and CDateInput, defaultTime on CTimePicker and CTimeInput, defaultStartDate / defaultEndDate on CDateRangePicker, and defaultValue on COneTimePassword. Pass the value prop one-way instead: <CDatePicker date="2026-07-14" /> seeds the picker, which keeps managing itself. CDateInput and CTimeInput follow the same rule now — a one-way date / time no longer freezes the field; only a v-model binding hands the state over.

  • CAutocomplete, CMultiSelect: the per-option selected flags are a seed, ignored entirely when value or defaultValue is set, and they no longer re-apply on later renders of the same option. In CAutocomplete a flag applies once, when its option first appears. In CMultiSelect it applies only to the options the component starts with: options that arrive later never change the selection, and resetSelectionOnOptionsChange empties it and takes the marked options when the values change. With value set the reset only requests the empty selection through the change event.

  • Form controls answer a native form reset the same way, bound ones included. CAutocomplete, CChipInput, CCombobox, CDateInput, CDatePicker, CDateRangeInput, CDateRangePicker, CFormRange, CMultiSelect, COneTimePassword, CRangeSlider, CRating, CTimeInput and CTimePicker with a bound value used to keep it on a reset; they now ask for the value they started with through the events that report their value (change for CAutocomplete and CMultiSelect, update:modelValue for CFormRange, the update and change events for the rest) and show your value until you take it, so a page that resets its own state from the form’s reset gets that request after its handler. A reset brings CRating, CRangeSlider and CFormRange back to the value they started with rather than the current prop, COneTimePassword emits change only when the reset changes the code, and CStepper keeps the validation marks of a form reset a listener cancels.

  • CButton: a toggle button’s active is controlled when set — a click only emits click and the pressed state follows your prop; seed an uncontrolled toggle with defaultActive. Without either prop nothing changes.

  • CCalendar: equal re-renders no longer reset the view. A parent re-rendering with an equal calendarDate, startDate or endDate (a fresh Date object holding the same value) used to yank back the navigated month and cancel an in-progress range selection; only a real value change syncs now. Month names also follow locale and monthFormat changes at runtime.

Validation state

Deprecated One validation-state prop replaces the valid and invalid booleans on every form control, field and picker, and on CFormFeedback. validation-state="invalid" renders is-invalid and sets aria-invalid on the control, "valid" renders is-valid, and any custom state from the $form-validation-states Sass map renders is-{state} — two independent flags could neither express a third state nor refuse valid and invalid at once. On the components that had them in v5 the booleans keep working as deprecated aliases (with both set, invalid wins, where they used to stack), and are ignored whenever validation-state is set; CCheckbox, CChipInput, CCombobox, CDateInput, CDateRangeInput, CNumberInput, CRadio, CSwitch and CTimeInput take validation-state only. Four side effects worth knowing:

  • feedback follows the state: it renders only while validation-state is set, styled after it, and describes the control in every state, not only the invalid one.
  • Every control that reads validation-state="invalid" now sets aria-invalid="true", except CCombobox, whose toggle is a button and takes only the message in aria-describedby; a control without a validation state still sets none.
  • Breaking validation-state="invalid" (or the deprecated invalid) blocks the submit on CFormInput, CFormSelect, CFormTextarea, CNumberInput, CPasswordInput, CCheckbox, CRadio, CSwitch, CFormCheck and CFormSwitch, with the text of the invalid feedback as the browser’s message, the way it already did on the fields that build their own markup. Each control emits update:validationState with undefined when the user changes its value or the form is reset; bind it with v-model:validation-state (with the deprecated invalid, set it to false on that event instead), or a form you gave an invalid state stays blocked until you clear it yourself. See Validation.
  • Breaking CMultiSelect, CChipInput, CCombobox, COneTimePassword, the date and time fields, the pickers and CAutocomplete take and show their validation state the same way, described under Form components. A field a validation reports shows the state on the component’s frame, and <CForm> and CStepper leave the field that carries the value to the component. After taking the result over with preventDefault() in a validate listener, keep event.isValid rather than calling checkValidity(): the call reports every invalid field again, and the components then show their error.

Help text and feedback ids

text and the feedback get ids of their own. A form control used to hand its aria-describedby to the text and to the feedback as their id, so the help text and the error shared one id: the control read the help text and never the error, a valid control with feedback-invalid was described by the hidden error, and an aria-describedby that pointed at an element of the page gave that id to a second element. Now text, feedback, feedback-invalid and feedback-valid get generated ids, and the control lists them in its own aria-describedby after the one you pass: the text always, feedback while validation-state is set, feedback-invalid only while the control is invalid and feedback-valid only while it is valid, whether that state comes from validation-state or, in a data-coreui-validate form, from the browser’s :user-invalid and :user-valid (the date and time fields and the pickers use the field’s own verdict instead). A validation-state you set takes precedence. Pass aria-describedby only to point at elements of your own; a value you passed so that the text would carry it is no longer needed, and CSS or scripts that found the text by that id need another hook. CFormControlWrapper and CFormControlValidation replace their undocumented describedby prop with description-id, the prefix the ids are built from (<description-id>-label, -text, -feedback, -feedback-invalid and -feedback-valid).

  • In the years view the double arrows and Page Down / Page Up turn the calendar by the twelve years a page shows instead of ten, so a turn no longer repeats two years of the previous page.
  • In the years view the year button goes back to the view that picks the date instead of doing nothing, and it is disabled in year selection, where the years view is the one that picks.

A page that translates the other calendar labels translates these two as well.

Such an adjacent day is no longer aria-selected either, and the dayCell slot gets isDisabled: true and isSelected: false for it, so the copy of a picked date that fills the next panel reads as unavailable filler.

The months and years views of a day range only navigate and keep it on the ends, and isSelected still marks only the ends.

Before, each field described the day alone, so a selected week reported only the day holding its start or end date as selected.

The month, quarter and year views, the arrow keys and paging keep the year the same way. Years before 1 cannot be picked, as dates before minDate cannot: their cells are disabled, and the arrow keys and paging stop at 1 January of year 1.

Two digits still expand to the century within 50 years of today. The value reported for week, month, quarter and year selection writes the year in at least four digits (0026-05, where it was 26-05), so it reads back as the same year.

CCallout

  • New: theme. It sets the color context and renders a .theme-* class, so the callout also picks up a theme class placed on any element above it. The class colors the leading edge and tints the border.

CCard

  • Breaking text-color is removed. It wrote a single fg-{value} class, and the values it listed from v5 (body-secondary, body-tertiary, *-emphasis, black-50, white-50) had no rule in v6, so the text kept its inherited color. Put the color utility on the component instead: class="fg-2" for body-secondary, fg-3 for body-tertiary, fg-emphasis-primary for primary-emphasis, text-body-emphasis for body-emphasis, fg-white fg-50 and fg-black fg-50 for white-50 and black-50, and fg-{color} for a theme color.

CCardHeader, CCardFooter and a CListGroup placed directly in the card take --cui-card-spacer-x as their inline padding, so their text lines up with the body; the header and footer keep .5rem of block padding. The border reads --cui-border-color instead of --cui-border-color-translucent, except on a translucent card, and the radius is --cui-radius-7 (.75rem; v5 used .375rem). A card filled with textBgColor or color keeps that neutral frame; add the matching border-<color> class to frame it in the fill colour. To keep the v5 look, set --cui-card-spacer-y and -x to var(--cui-spacer-5) and --cui-card-border-radius to .375rem on the card.
  • Breaking CCardLink is removed. .card-link is gone from v6 — it existed to space sibling links with an inline margin, which only worked while they were inline, and .card-body is a flex column with --cui-card-body-gap now. Wrap the links yourself: <div class="hstack gap-4"><CLink …/><CLink …/></div>.
  • Breaking .card-body is a flex column. It spaces its children with --cui-card-body-gap and zeroes their block margins, so nothing in a card needs .mb-* any more. Two consequences for existing markup: a direct child takes its natural width rather than filling the card — add .w-100 where a block child has to stretch — and text-align no longer moves a button or a link, because they are flex items. Use .mx-auto or .ms-auto instead.
  • Stacked sections are divided by a single rule. A <CCardBody>, a list group or a bottom image that follows a top image, a body or a list group draws a divider above itself in the card’s own border, so two bodies in a row, or an image above a body, no longer sit with nothing between them, and a border utility or a theme on the card carries over to every divider. A section hidden with hidden or .d-none does not count. <CCardHeader> and <CCardFooter> draw their own divider, as before.
  • <CCardGroup> squares the corners at each seam along the writing direction. The rules named the physical corners, so a right-to-left group squared its outer corners and rounded the ones that meet. A list group at the edge of a grouped card is squared like the other sections.
  • Breaking color no longer takes a gradient. v6 removes the bg-*-gradient utilities the value mapped to. Reach for .bg-gradient alongside the color if you want the sheen.
  • Gradient bars. --cui-progress-bar-bg-image paints the bar with an image over its colour, so a gradient is one variable in style; stripes layer over it and have their own --cui-progress-bar-stripes and --cui-progress-bar-stripe-color.
  • segmented and segments on CProgress. The track becomes a row of rounded segments — --cui-progress-segment-min-width wide and --cui-progress-segment-gap apart, or at most segments of them — and the bar fills whole segments only, recounted as the track resizes. Corners come from --cui-progress-segment-border-radius.
  • Breaking .card-header-pills is gone. It pulled the pill row out to the header’s padding edge, which is wrong for pills — they carry their own background, so flush against the inner edge they touch the border. Drop the class from <CNav variant="pills">.
  • Breaking <CCardGroup> attaches from a container query, not a media query. The sm breakpoint is the width of the nearest query container, not the viewport. Mark an ancestor with .contains-inline; without a container the query has nothing to read and the cards stay stacked at every width. The same applies to <CListGroup> with layout="horizontal-*".
  • New: theme paints the card’s frame and caps with a theme color, with contrast text in the header and footer; the body keeps the card background. It is a different axis from color, which still applies the bg-{color} utility across the whole surface, and from textBgColor. Put the class on a single section — <CCardFooter class="theme-danger"> — and only that section follows it.
  • New: variant="subtle" swaps the solid fill for the theme’s subtle background and border, and new: translucent blurs whatever is behind the card and thins the caps to match. They are independent — .card-subtle and .card-translucent combine — which is why translucent is a boolean of its own and not a second variant value.
  • New: layout="row" lays a card out along the inline axis, with <CCardImage orientation="start" | "end"> for an image cap on either side. It replaces the <CRow class="g-0"> + <CCol md="4"> recipe, which needed a wrapper per section and drew no divider between them.

CCarousel

  • Breaking The carousel runs on native CSS scroll snapping. The track is a scroll container, so dragging, swiping, momentum and trackpad scrolling come from the browser; the component layers on the controls, indicators, autoplay and active-slide tracking. There is no .slide class any more, and programmatic navigation animates the scroll position instead of translating slides.
  • Breaking index is renamed to activeIndex, and the carousel now follows post-mount changes — updating the prop slides to the new index.
  • Breaking touch and wrap are gone. Touch gestures are the scroll container’s own, and ends supersedes wrap: 'loop' (default) continues seamlessly where the layout allows, 'wrap' jumps to the other end, 'stop' disables the matching control at each end.
  • Breaking CCarouselItem drops direction — the scroll position, not a per-slide class, decides how a slide enters.
  • New: autoplay (turns off for good once the user interacts), playPause with pauseLabel / playLabel (WCAG 2.2.2), keyboard, center, variableWidth, and the --cui-carousel-items / -gap / -peek custom properties for multi-item layouts.

CChip, CChipSet, CChipInput

  • Breaking CChipInput carries its chips in a hidden <textarea>, submitted only once you name it. It took a generated name when the prop was not set, so a form carried a key nobody chose; the field is now named only by the prop. It is a <textarea> instead of an <input type="hidden">, because the browser leaves a hidden input out of validation, and the submitted value is the same, the chips separated by commas. With it CChipInput takes required, validation-state, update:validationState and the feedback props, blocks the submit while it is empty and required, and a native form reset puts back the chips it started with. A disabled CChipInput is no longer submitted, like any disabled field. It renders its messages after the frame, so the component has two root nodes; reach the frame through the exposed rootRef. See Validation.

  • Breaking CChip loses the active prop. selected is the single prop that renders the .active class on any chip; the toggle behaviour, ARIA state and the filter check icon apply only with selectable or filter. Replace active with selected on a static chip.

  • Breaking The chips expose real roles. A selectable CChipSet is a horizontal role="listbox" (with aria-multiselectable outside single mode) whose chips are role="option" carrying aria-selected; a non-selectable set is a role="group". A standalone selectable CChip is a toggle button (role="button") and reflects its state through aria-pressed instead of aria-selected.

  • Breaking aria-disabled is stamped only on a chip that carries a role. On a role-less chip the attribute was invalid; the disabled class and the removed interactivity carry the state.

  • Breaking CChipInput no longer stamps aria-disabled/aria-readonly on its container. The container is a generic element, so those attributes were invalid on it; the native disabled/readonly states of the inner input carry the semantics.

  • Adding and removing chips is announced. CChipSet and CChipInput announce each change through announce(); the wording is configurable through ariaAddedAnnouncement and ariaRemovedAnnouncement.

  • Every remove button names its chip. CChip and CChipSet named each remove button Remove, so a set read the same name for every chip; the button is Remove <text> now, as CChipInput and CMultiSelect already did. aria-remove-label (and aria-chip-remove-label on CMultiSelect) takes a string, where {label} stands for the chip’s text and is appended when missing, or a function of the text for a different word order. A label that already spelled the text out now repeats it; drop it or use {label}.

  • A selectable chip hides its remove affordance. A chip with a role — a selectable chip, which is a toggle button, or an option in a selectable set — gets a <span aria-hidden="true"> instead of a <button> inside it, so its name is its text and a control is no longer nested in a button. Backspace and Delete remove it from the keyboard, the affordance from the pointer.

  • A chip set is one tab stop. CChipSet and CChipInput gave every chip tabindex="0", so Tab walked through each chip. The chip that last had focus is the tab stop now, the first chip until then, and the arrow keys move between the rest, chips without a value included. CChip computes its tabindex from selectable, removable and disabled; a tabindex passed to it is ignored.

  • CChipInput keeps focus among the chips after a removal. Removing the focused chip sent focus to the text input; it now moves to the next chip, else the previous one, and reaches the text input once no chip is left, the rule CChipSet follows.

CCloseButton

  • Breaking The white and dark props are gone. The glyph is drawn with a CSS mask and takes the button’s inherited color, so on any surface that paints its own text — a .text-bg-inverse toast, a dark navbar’s offcanvas — it is already the right color, and neither prop has anything left to do.

    white rendered .btn-close-white, which v6 removed. dark stamped data-coreui-theme="dark" on the button, which used to match a rule that inverted the glyph through a filter; that rule went with the mask, and what the attribute still sets — the shadow strength and color-scheme — reaches nothing the close button draws. To flip a region, put the attribute on the section and give it a surface (.bg-body.text-body); the button follows the text it inherits.

CCollapse

  • The stylesheet owns the animation where the browser can interpolate a size to auto. CCollapse no longer writes an inline height/width there — driving the size from the component as well would run the same expansion from both ends. Browsers without interpolate-size keep the measured path, and both read the duration and easing from --cui-transition-collapse-duration / -timing instead of a hardcoded 350 ms.
  • Breaking .collapse stays on the element for the whole run. It used to be dropped while .collapsing was on, which in v6 means the element misses interpolate-size and the transition the stylesheet puts on .collapse — so the CSS path would not animate at all. .show also lands at the start of the opening run rather than at its end, because the stylesheet reads it as the open state and animates towards it. Custom CSS that keyed off the old combinations needs updating.
  • New: hiddenUntilFound hides the collapsed area with hidden="until-found" rather than taking it out of the layout, so find-in-page searches it and the browser expands it on a match. The show event fires when that happens — set show from it, or the stylesheet hides the content the reader was just sent to. Off by default; the attribute is left off entirely below Chrome 102 / Firefox 148 / Safari 26.2.

CContextMenu

  • New component. <CContextMenu> is the trigger area: a right-click, or Shift+F10 / the Menu key while it has focus, opens the <CMenuContent> inside it at the pointer and suppresses the browser’s own menu. It is a CMenu positioned against the pointer with position: fixed, so items, submenus, keyboard navigation and autoClose are the Menu’s. Focus moves into the menu on open and returns to the area on close; the page does not scroll while the menu is open. A row’s own @contextmenu handler runs first — prevent the event there to keep both menus closed.

CDateInput, CDateRangeInput, CTimeInput

  • Breaking A required field blocks the form. The value moved from an <input type="hidden">, which the browser leaves out of validation, to a <textarea> laid invisibly over the field, with tabindex="-1" and aria-hidden="true"; a textarea, unlike a text input, leaves Enter submitting a form that has no submit button. A required field that is empty, incomplete or holds a rejected date now stops the submit, and the browser puts focus on its first empty section with its own message over the field. The field marks itself invalid whenever a validation reports it, also outside a submit, and its value field fires native input and change events when the date changes. This applies to the pickers and to both ends of a date range as well. Code that selects input[type="hidden"] inside the field needs .form-date-time > textarea.
  • Breaking A given state is a verdict on one value. validation-state="invalid" now blocks the submit, with the text of the message after the field, until it is cleared. The user’s next change of the value and a native form reset emit update:validationState with undefined before the change is reported, so bind the state with v-model:validation-state; a value your code sets keeps the state. Without a given state the field shows what a validation reports and, in a form with validate, the :user-invalid and :user-valid states of its value field, as a native field does. aria-invalid sits on the sections, not on the group, and an aria-invalid you pass is not read as a state. This applies to the pickers and to both ends of a date range as well.

CDatePicker, CDateRangePicker, CTimePicker

The pickers are no longer monoliths. Each is a composition of a section field, a calendar or time selection, and an anchored panel — which is what removes most of the props below: the field and the panel are now the same primitives you can use directly.

  • Breaking CDatePicker is its own component. In v5 it was a thin wrapper over CDateRangePicker and inherited its props; it now has its own, single-date API (date, v-model:date).

  • Breaking The button-configuration props are gone — todayButton, todayButtonColor, todayButtonSize, todayButtonVariant, cancelButton*, confirmButton* and rangesButtons*. Project the content instead: the footer scoped slot receives the picker’s context, so a button you render yourself can act on the picker and read its state. The same context is available to any descendant through useDatePicker(), useDateRangePicker() and useTimePicker().

    <CDatePicker>
  <template #footer="{ today, clear, close, isDateSelectable }">
    <CButton :disabled="!isDateSelectable(new Date())" size="sm" @click="isDateSelectable(new Date()) && today()">Today</CButton>
    <CButton size="sm" @click="clear">Clear</CButton>
    <CButton size="sm" @click="close">OK</CButton>
  </template>
</CDatePicker>

  • Breaking CDateRangePicker: ranges is a projected region too. It is a scoped slot receiving the context, so a preset button calls setRange with its own dates; rangesButtonsColor/-Size/-Variant are gone with it. The range is startDate/endDate (one-way to seed, v-model to bind), and the two fields take startName/endName.

  • A picker action shows its date in the calendar. setRange, reset, setDate and today from the picker’s context turn the calendar to the date they set (a range’s start, else its end) in the view it is in, also when the value does not change and over a calendarDate you pass, so a preset clicked again after browsing brings its range back. clear and an invalid date leave the calendar where it is; a typed date, a picked time and the dates you pass move it as before.

  • Breaking A date field is submitted only once you name it. CDatePicker and CDateRangePicker built the name of their inputs from id when name was absent, so <CDatePicker id="delivery" /> posted delivery-date and the range posted delivery-start-date / delivery-end-date. That fallback was deprecated in 5.3.0 and is gone: an id names the element for a label, it does not put the value in the payload. Pass name, or startName/endName, for the field to reach the server.

  • Breaking The field props are gone: inputDateFormat, inputOnChangeDelay, inputReadOnly, placeholder, separator. The value is a mask now — pass format (or a section layout) and, for the placeholder text, one prop per section — dayPlaceholder, monthPlaceholder, yearPlaceholder and the rest. The range placeholder also named the two fields; CDateRangePicker names them with ariaStartLabel and ariaEndLabel now (“Start date” and “End date” by default), or with floatingLabels when set. Use readOnly for a read-only control and separatorIcon for the artwork between the two range fields.

  • Kept. timepicker still adds the time half to CDatePicker, now as a row of time selects under the calendar rather than a second panel beside it. Because the two halves own different parts of one value, a picker with time does not auto-close: picking a day keeps the time and picking a time keeps the day. hours, minutes and seconds narrow what the time half offers.

  • Changed. With timepicker, a min-date or max-date that carries a time of day bounds the time on its day: the time selects disable the hours, minutes and seconds before min-date or after max-date there, a time the panel sets beyond the limit (the current time when that day is picked) moves to the limit, and a typed time beyond it marks the field invalid. A limit without a time of day covers its whole day.

  • Breaking hours is 0 to 23 in every locale. v5 read the list and the filter in the column’s cycle, so on a locale whose v5 columns were 12-hour (the ones that write AM and PM in Latin letters, such as en-US) :hours="[1, 3, 5, 7]" meant 1, 3, 5 and 7 in the morning and in the afternoon, 12 meant noon and midnight, and a filter received 1 to 12. The 12-hour column still lists 1 to 12 next to AM/PM, but each entry now stands for the 24-hour hours the list allows: picking an hour that only one period allows sets that period, and the period the picked hour does not allow is disabled. To keep such a list, name both halves: :hours="[1, 3, 5, 7, 13, 15, 17, 19]", with 0 and 12 for 12. More locales get 12-hour columns than in v5, because the columns follow the field’s clock, Korean, Traditional Chinese, Arabic and Mexican Spanish among them; their v5 columns were 24-hour, so a list written for them keeps its meaning. The day period column also speaks the locale, 오전 and 오후 in Korean, where it read “AM” and “PM”. A longer name widens its column, so --cui-time-picker-cell-width is now the narrowest a cell gets, and --cui-time-picker-cell-padding-x keeps the name off the cell’s edges.

  • Breaking The time picker’s roll classes lose the roll infix, and the date picker’s time controls carry its own name. .time-picker-roll-col and .time-picker-roll-cell are .time-picker-col and .time-picker-cell, with --cui-time-picker-col-* and --cui-time-picker-cell-* in place of their -roll- spellings; .time-picker-roll was always present on .time-picker-body, so it is gone rather than renamed, and --cui-time-picker-body-padding went with it. .time-picker-inline-icon and .time-picker-inline-select are .date-picker-time-icon and .date-picker-time-select, with --cui-date-picker-time-* tokens, because they belong to the date picker’s panel. Custom CSS written against any of these names needs the new one.

  • Breaking CTimePicker: variant is gone. Each picker has one time rendering — the time picker shows the roll, and the date picker’s time half shows the selects, which is what v5 rendered inside a date picker with time. The selects ship in the date picker stylesheet, so a page that only uses the time picker no longer downloads them.

  • Breaking The time selection is one tab stop. Tab reaches the body once, Arrow Left and Arrow Right move between the hour, minute, second and AM/PM parts and stop at the ends, and Arrow Up / Arrow Down change the focused value. Both renderings answer the same keys.

  • Breaking CTimePicker: ampm is gone. The hour cycle follows the field’s mask when it names one (HH vs hh a) and the locale otherwise.

  • Breaking closeOnSelect and previewDateOnHover are gone. A complete selection closes the panel unless a footer projects actions the user still needs.

  • Breaking indicator is gone. The button that opens the panel is always rendered; the pickerIcon slot replaces its artwork. The button that clears the value is the one you can switch off, with cleaner.

  • Breaking The v1 shell class names are gone: date-picker-input, date-picker-input-wrapper, date-picker-input-preview, date-picker-cleaner, time-picker-input, time-picker-cleaner, and the -dropdown panels are now .date-picker-popup / .time-picker-popup.

  • The panel is rendered through a portal by default (portal), into container when given. It is built on the first open, not on mount.

  • New props across the family: cleaner and the cleanerIcon slot, the pickerIcon slot, disabled, show / v-model:show with the show/hide events, size, and the accessible labels ariaCleanerLabel / ariaPickerLabel.

  • CDatePicker and CDateRangePicker emit view-change from their calendar, with the starting view each time the panel opens.

  • Pickers open on the platform’s dropdown keys. Alt+ArrowDown and F4 open the panel and move focus into it — onto the selected date, else today or the minDate / maxDate today falls outside of, also when that date cannot be picked. The field’s own arrows keep editing the value, as <input type="date"> does. Opening with the mouse moves focus in too.

CDropdown

  • Placements are mirrored once now, by Floating UI. The -start/-end half of a placement is logical — Floating UI resolves it from the writing direction of the floating element — and the library was mirroring it a second time, which cancelled it. In a right-to-left context that moves every placement whose suffix you set: alignment="end" now hangs from the inline end, and an explicit placement="bottom-start" opens from the right edge instead of the left. The sides are the other way round: Floating UI never mirrors left/right, so a logical start/end side still maps to the physical one the direction asks for and dropend/dropstart still swap. Also in this change: a dropup aligned to the end keeps its side (it resolved to bottom-end before), direction="center" resolves to bottom rather than bottom-start, a submenu in a right-to-left context anchors to the top of its trigger rather than the bottom, and useDropdownWithFloating asks Floating UI for a plain bottom-start. CCardBody became a flex column in v6, so CWidgetStatsA stacked its menu under the figure instead of putting it in the corner, CWidgetStatsF stacked its icon above the text, and CWidgetStatsD stacked its values instead of laying them in a row. The blocks carry the flex-row and w-100 those layouts now need.
